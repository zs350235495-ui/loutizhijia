## 序言：为什么每位飞行员都需要一条“备用跑道”？

你在飞行滑行过程中，是否遇到过这种尴尬至极的瞬间？

1. **主力套餐月底耗尽**：月度订阅套餐的 100GB 或 200GB 流量在月底最后三天提前告罄，但距离结算刷新日还有好几天，为了看几篇网页重新买一个月付套餐又显得极度划算不高；
2. **主跑道突发严重拥堵**：遇到特定时期或主机场上游机房故障拔线，所有节点瞬间“全红超时”，你手里手握急需提交的 GitHub 提交或 OpenAI 关键对话，却只能干瞪眼；
3. **轻度受众不需要月付**：家里长辈或者自己只是偶尔查查资料、收发 Google 邮件，一个月用不到 5GB 流量，按月扣费的连续订阅套餐完全是白白浪费钱。

针对这些痛点，**“按量付费（Pay-As-You-Go）/ 不限时流量包”** 应运而生。一次购买，流量永不过期（或有效期长达数年），用多少扣多少。

然而，按量付费模式也是机场圈商家“割韭菜”与“资金盘跑路”的重灾区。本篇文章中，鹅将带你彻底拆解按量付费跑道的底层逻辑、商业坑点，并为你盘点实测优质的备用跑道选型。

## 一、 按量付费与不限时流量包的底层商业坑点拆解

许多飞行员认为“不限时流量包买一次能用几年，简直赚翻了”。但站在站长鹅的视角看，不限时套餐在商业模式上天然存在着**现金流衰减**与**商家跑路风险**。

### 1. 商家为什么讨厌“不限时流量包”？
机场的带宽成本（无论是 BGP 中转还是 IPLC 专线）都是**按月或按年向上游机房支付**固定月租的。
如果一个机场卖出了大量的“不限时流量包”，用户一次性付了 50 元买 500GB 流量，然后分摊在 3 年内慢慢消耗。对于商家而言：
- 第一期收到了大量现金；
- 随后的 36 个月里，用户一直在消耗机场的月租带宽，却没有产生任何续费现金流。

当后续新用户增长放缓，商家收到的新增资金无法覆盖每月固定的服务器机房月租时，资金链就会瞬间断裂。这就是为什么 **80% 提供大容量廉价不限时套餐的新机场，会在上线 6~12 个月内悄无声息地关闭网站并 Telegram 退群**。

### 2. 按量付费跑道选型的“四大生死铁律”

| 避坑维度 | 危险操作 (准备吃亏) | 正确姿势 (鹅的建议) |
| :--- | :--- | :--- |
| **商家资历** | 购买刚成立不到半年的“新开小机场” | 严格限定在**运营 3 年以上、财务状况健康的老牌机场** |
| **单次充值金额** | 贪便宜直接充值 200~500 元超大包 | 单次购买金额控制在 ￥30 ~ ￥80 元之间，用完再补 |
| **节点倍率** | 忽略倍率，误用 5x/10x 节点导致流量瞬间清空 | 认准全站 1.0x 倍率，或配置软件自动避开高倍率节点 |

## 三、 实操教程：如何在客户端中配置“自动备用切路”？

买好了备用跑道，千万不要手动来回切换订阅。利用现代代理客户端（如 Clash Verge Rev、Stash 或 Shadowrocket）的**自动回退策略组（Fallback Group）**，可以实现主线路断流时毫秒级自动切换到备用跑道。

### 1. Clash Verge Rev 配置策略组逻辑

在 Clash 配置文件的 `proxy-groups` 节点下，添加一个类型为 `fallback` 的策略组：

```yaml
proxy-groups:
  - name: 🪿 自动备用切路组
    type: fallback
    url: 'http://www.gstatic.com/generate_204'
    interval: 300
    proxies:
      - ✈️ 主机场-香港专线 01  # 首选主力跑道
      - ✈️ 主机场-东京专线 01  # 次选主力跑道
      - 🛞 备用机场-按量不限时 01 # 应急备用轮胎 (仅在前两者超时时触发)
```

### 2. 工作原理
- 客户端每隔 300 秒向 Google 连通性探针发送测试包；
- 只要首选的“主机场专线”响应正常，所有流量 100% 走主机场，**不消耗按量付费备用包的一丁点流量**；
- 一旦主机场出现炸节点或遭遇 QoS 拔线导致超时，“自动备用切路组”会立刻无缝接管网络请求，确保你的网页不掉线、视频不中断。
