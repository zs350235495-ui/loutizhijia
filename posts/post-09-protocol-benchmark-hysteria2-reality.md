## 序言：协议演进史与技术迷雾

在科学上网技术发展的十几年中，代理协议经历了几次划时代的迭代：
1. **第一代：Shadowsocks / Trojan / VMess (TCP 基础协议)**
2. **第二代：VLESS + XTLS / gRPC (握手优化与去特征化)**
3. **第三代：VLESS-Reality (偷取真实 TLS 证书) & Hysteria 2 (基于 QUIC/UDP 的拥塞控制)**

许多飞行员在面对客户端里密密麻麻的协议选项（SS, VMess, VLESS-Reality, Hysteria 2, Tuic v5）时，往往一头雾水。

为什么有的协议在晚高峰能强行拉满速度？为什么有的协议连接极其稳定但速度上限不高？本篇文章中，鹅将带你硬核拆解 **Shadowsocks、VLESS-Reality 与 Hysteria 2** 三大主流协议的技术底层逻辑、抗封锁原理及弱网表现。

## 一、 硬核原理拆解：三大协议的物理底层机制

```
【三大协议握手与传输架构对比】:

Shadowsocks (传统 TCP):
客户端 ──> [明文/固定特征 AES 加密] ──> GFW (DPI 主动探测/重放攻击) ──> 很容易封锁 IP

VLESS-Reality (TCP + TLS 伪装):
客户端 ──> [偷取真实网站 SNI/证书 (如 Apple/Microsoft)] ──> GFW (误以为是访问苹果官网) ──> 极强抗封锁

Hysteria 2 (UDP + 自定义拥塞控制):
客户端 ──> [UDP 暴力发包 + BBR 拥塞加速] ──> 绕过 TCP 丢包重传等待 ──> 弱网跑满带宽
```

### 1. Shadowsocks (SS / SS-2022)
- **底层传输**: 基于标准 TCP 协议。
- **核心机制**: 使用对称加密（AEAD 算法，如 `aes-128-gcm` 或 `222-blake3`）保护 payload。
- **致命弱点**: 在直连公网环境下，GFW 能够通过主动探测（Active Probing）和重放攻击（Replay Attack）识别出节点的响应特征，从而批量阻断 IP。但在**专线（IPLC/IEPL）内网**中，由于不过 GFW，Shadowsocks 依然拥有最低的 CPU 开销与极高的传输效率。

### 2. VLESS-Reality (Xray 内核)
- **底层传输**: 基于 TCP + TLS 1.3 协议。
- **核心机制**: 彻底废弃了服务端自行配置域名证书的繁琐流程，转而**“偷取（Borrow）”真实合规大厂网站的 TLS 证书**（如 `apple.com`、`microsoft.com`）。
- **抗封锁表现**: 在 GFW 眼中，你的所有流量与访问苹果/微软官方服务器的合法 HTTPS 流量完全一致。因为 GFW 不敢贸然切断苹果或微软的服务器 IP，所以 Reality 具备**近乎无解的公网抗封锁生存能力**。

### 3. Hysteria 2 (Hy2 / 基于 QUIC)
- **底层传输**: 基于 UDP 协议（修改版 QUIC 协议）。
- **核心机制**: 传统 TCP 协议遇到 10% 的丢包时，会强行将发送窗口减半并等待重传，导致网速断崖式下跌。而 Hysteria 2 采用了自定义的拥塞控制算法，**在丢包率高达 30% 的弱网下，依然暴力持续发包**，将物理频宽强行拉满。
- **潜在风险**: 部分地区的运营商（如部分省份的移动/联通）对 UDP 协议实施了极其严苛的 **QoS 限速或 UDP 阻断**。如果在这些地区使用 Hy2，可能会遭遇断流或被直接丢弃 UDP 封包。

## 二、 弱网环境与抗封锁表现横向对比

在晚高峰 (21:00) 丢包率 20%、RTT 延迟 150ms 的模拟弱网环境下，我们对三大协议进行了打点与测试：

| 对比维度 | Shadowsocks (SS-2022) | VLESS-Reality | Hysteria 2 (Hy2) |
| :--- | :--- | :--- | :--- |
| **抗 GFW 主动探测** | 🔴 弱（仅限专线使用） | 🟢 **极强 (偷取大厂 TLS)** | 🟠 中等（依赖 UDP 混淆） |
| **高丢包环境吞吐量** | 🔴 差 (TCP 降速严重) | 🟠 中等 (标准 TCP 机制) | 🟢 **极强 (UDP 暴力补包)** |
| **运营商 QoS 抵抗** | 🟠 一般 | 🟢 **极强 (伪装标准 HTTPS)** | 🔴 差 (易受部分地区 UDP QoS 限速) |
| **设备 CPU/电量消耗** | 🟢 **极低** | 🟠 中等 | 🔴 较高 (UDP 高频打点) |
| **最佳应用场景** | **IPLC / IEPL 物理专线** | **公网直连 / 应急抗封锁** | **高丢包移动宽带 / 弱网拉速** |
