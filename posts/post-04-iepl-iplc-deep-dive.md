## 一、 硬核技术拆解：IPLC 与 IEPL 到底有何区别？

在机场商家的宣传单上，我们经常看到 **IPLC** 和 **IEPL** 这两个高级词汇。它们究竟是什么？两者有什么本质差异？

```
【普通公网线路传输路径】:
用户电脑 ──> 国内公网 ──> GFW 公网防火墙 (检查/QoS丢包) ──> 国际公网骨干网 ──> 海外落地机房

【IPLC / IEPL 物理内网专线传输路径】:
用户电脑 ──> 国内入口机房 ──> [物理光缆内网直连/点对点] ──> 海外落地机房 (完全绕过 GFW 公网)
```

### 1. IPLC (International Private Leased Circuit，国际私有专线)
- **底层架构**: 基于传统的 SDH/WDM 物理传输网络，本质上是运营商（如中国电信、中国联通、电讯盈科等）在两地机房之间铺设的**端到端专用电路**。
- **核心优势**: 流量完全在运营商内网闭环传输，**不经过任何 GFW 审查节点**，没有任何公网 QoS 限速。
- **缺点**: 属于 OSI 第二层（数据链路层）传输，协议开销相对较大，且由于是租用整条固定频宽电路，扩展成本极高。

### 2. IEPL (International Ethernet Private Line，国际以太网专线)
- **底层架构**: 现代化的以太网专线传输，基于 OTN (光传送网) 技术。
- **核心优势**: 具有更高的带宽弹性和更低的抖动率，支持以太网帧的直接封装，延迟更低、丢包率更趋近于 0。
- **协议兼容**: 对 UDP 游戏封包、RTC 实时音视频通话的兼容性优于传统 IPLC。

### 3. IPLC vs IEPL vs 公网 BGP 性能全方位对比

| 对比维度 | 公网 BGP 隧道 / 中转 | IPLC 物理专线 | IEPL 物理以太网专线 |
| :--- | :--- | :--- | :--- |
| **物理传输介质** | 共享公共互联网骨干网 | 运营商专用物理光缆 | 运营商高精 OTN 以太网专线 |
| **是否过 GFW** | 是（公网出口经过审查与 QoS） | **否（物理内网绕过）** | **否（物理内网绕过）** |
| **晚高峰丢包率** | 15% ~ 60% 严重波动 | 0% ~ 0.2% 极低 | **0.0% 几乎为零** |
| **网络延迟 ping** | 120ms - 280ms 剧烈抖动 | 25ms - 45ms 极稳定 | **20ms - 40ms 极低抖动** |
| **运营商成本** | ￥5 ~ ￥15 / Gbps | ￥150 ~ ￥300 / Mbps | ￥200 ~ ￥450 / Mbps |
| **适合用户群体** | 影音娱乐、轻度查资料 | 外贸商务、AI 生产力 | 高频交易、硬核电竞游戏、高端企业 |

## 二、 成本迷雾：高端专线机场为什么这么贵？

很多用户不理解，为什么专线的价格居高不下？这里涉及到了上游机房的**计费模式差异**。

1. **普通服务器是按流量（GB/TB）计费的**：比如香港或美西的 VPS，1TB 流量的公网成本可能只需要几块钱人民币。因此低价机场可以通过高超售比例来压低月费；
2. **物理内网专线是按带宽（Mbps/Gbps）按月独占计费的**：一条 1Gbps（1000兆）的广港或沪日 IPLC 内网专线，运营商每月的硬性租金高达 **数万至十几万元人民币**。

这意味着，无论用户这个月用不用网络，机场主都必须向中国电信或联通支付数万元的固定机房月租。为了保证每位付费用户在晚高峰都能分到充足的专属带宽，高端专线机场**必须严格限制超售比例，并提高单人订阅单价**。

## 三、 真假专线识别指南：如何避免花专线的钱买到假中转？

由于“专线”概念利润丰厚，市场上出现了大量包装成 IPLC 的“伪专线（假专线）”。

### 伪专线的常见套路：
1. **公网隧道伪装**：使用普通的阿里云/腾讯云公网节点，套上一层 WebSocket 或 Hysteria 2 隧道，就宣称是“IPLC 专线”；
2. **入口专线，出口公网**：国内入口确实是专线，但在中途某个节点被解包放回了公网，依然会被 GFW 拦截和 QoS 限速；
3. **高倍率陷阱**：表面上月费 20 元，但所有“专线节点”都打上了 **5x 甚至 10x 扣费标记**，实际上看一个小时视频就扣掉几百 G 流量。

### 🪿 鹅的硬核检测三部曲：
- **第一步：看 TraceRoute 追踪**：真正的 IPLC 内网专线，在客户端使用 `traceroute` 或 `MTR` 工具测试时，跳数（Hops）极少，且中间不会出现公网骨干网（如 202.97 / 59.43 等公网 IP）的路由信息。
- **第二步：测试晚高峰丢包率**：在晚上 21:30，使用 `ping -c 100` 持续打点。真专线的丢包率必须强制小于 0.5%，延迟波动不得超过 ±5ms。
- **第三步：观察 UDP 游戏连通性**：连接 Steam 或 EA 游戏服务器，真专线能够提供稳定 NAT2/NAT1 环境，无突然掉线现象。
